Touch & Gesture

按下 · 滑动 · 缩放

移动端常用触摸事件怎么用

手机上用户用的是手指——按下、滑动、长按、双指缩放、摇一摇。这节课把触摸事件讲清、演示透，再用 4 个递进任务把它练熟。

📱 本页演示全部基于 touch 触摸事件，请用手机打开；没有手机时，可用浏览器的设备模式（F12 → 切换设备）体验单指操作。桌面端下页面会自动降级为鼠标模拟，方便查看日志。
1

手机上最容易踩的四个坑先避坑，再动手

写出来的现象真正的原因正确做法
按钮点一下变色，之后就一直是那个颜色 用了 :hover。手指没有“悬停”，触摸后状态不会自动撤销 改用 :active，或只在 @media (hover:hover) 里写 hover
点击按钮反应慢半拍 浏览器在等“是不是双击”，历史上会等 300ms 加 touch-action: manipulation，或直接用 touch 事件自己处理
拖动卡片时整个页面跟着上下滚 浏览器把手势优先给了页面滚动 容器加 touch-action: none（要接管手势）或 pan-y（只接管横向）
想判断“往哪滑、几根手指”，完全拿不到 只监听了 click，它只告诉你“点完了” 监听 touchstart / touchmove / touchend，从 touches 里取坐标与数量

🧠 一句话：手指是“多个触点 + 一段轨迹”。要跟手、要方向、要几根手指——这些都得靠触摸事件。

⚠️ 手机页面必备三件套（少一个都会出怪现象）：

① <meta name="viewport" content="width=device-width, initial-scale=1.0">，不写会整体缩小；
② -webkit-tap-highlight-color: transparent，去掉点击灰块；
③ 要接管手势的容器加 touch-action: none，否则浏览器会先滚动页面。

最小可运行骨架HTML
<!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8">
  <!-- ① 放 head 里，紧跟 charset -->
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>我的手势页面</title>
  <style>
    /* ② 全局去掉点击灰块（iOS / 安卓都认） */
    * { -webkit-tap-highlight-color: transparent; }
    body { margin: 0; font-family: "Microsoft YaHei", sans-serif; }

    /* ③ 只加在要接管手势的容器上，不是加在 body 上 */
    .lwj_pad {
      height: 180px;
      background: #151022;
      touch-action: none;        /* 这一块的手势归我，浏览器别滚 */
      user-select: none;         /* 长按不选中文字 */
      -webkit-touch-callout: none;
    }
  </style>
</head>
<body>
  <div class="lwj_pad" id="lwjPad">在这里滑动</div>
  <script>
    // ④ 事件与 touch-action 配对：容器管手势，页面其他区域照常滚动
    var lwj_pad = document.getElementById('lwjPad');
    var lwj_sx = 0;

    lwj_pad.addEventListener('touchstart', function (e) {
      lwj_sx = e.touches[0].clientX;
    }, { passive: true });

    lwj_pad.addEventListener('touchend', function (e) {
      var lwj_dx = e.changedTouches[0].clientX - lwj_sx;
      console.log(lwj_dx > 0 ? '向右滑' : '向左滑');
    });
  </script>
</body>
</html>
写错的位置会发生什么
touch-action:none 加在 body 上整个页面都滚不动了，用户无法上下浏览
只加了 touch-action，忘了阻止默认行为横向滑动时页面仍会上下轻微抖动，手感“发飘”
页面上没有任何 touch-action手指一拖，页面先滚，手势代码收到的是断断续续的坐标
给所有元素都加 touch-action:none整页失去滚动，等于把手机页面做成了“死页面”

🧠 判断口诀：哪块区域要“自己动手势”，就只给哪块加 touch-action；想让纵向还能滚动，就用 touch-action: pan-y。

2

四个触摸事件 + TouchList 对象核心模型

事件什么时候触发典型用途
touchstart手指刚按下记录起点、开始长按计时
touchmove手指在屏幕上移动（会连续触发很多次）跟手拖动、画板、判断方向
touchend手指抬起计算滑动距离与速度，决定是否翻页
touchcancel被系统打断（来电、消息横幅、手势返回）清理状态，避免“卡住”

事件对象里最关键的是 touches、targetTouches、changedTouches 三个列表：

三个列表的区别JS
lwj_pad.addEventListener('touchstart', function (e) {
  // touches：屏幕上所有手指（含其他元素上的）
  // targetTouches：只在当前元素上的手指
  // changedTouches：本次事件“变化”的手指（抬手时从 touches 里消失的就是它）
  var lwj_t = e.touches[0];              // 第一根手指
  console.log(lwj_t.clientX, lwj_t.clientY); // 相对可视区域
  console.log(lwj_t.pageX, lwj_t.pageY);     // 相对整个文档（含滚动）
  console.log(e.touches.length);         // 几根手指
});

🧠 为什么抬手时要用 changedTouches[0]？因为 touchend 触发时，那根手指已经从 touches 里移除了，用 touches[0] 可能拿到别的指头，甚至报 undefined。

🧩 为什么不用 click 就够了？click 只是“按下并抬起”的结果，拿不到中间过程——拖动时跟不了手、判断不了方向、也分不清几根手指。

✅ 你应该观察到：touchstart → 若干次 touchmove → touchend → 最后才是 click。而且移动距离越大，move 的次数越多——这就是“跟手”的原理。

⚠️ touchend 之后系统还会补发一次 click。如果两套逻辑都写了，就会“点一次执行两次”，记得二选一，或在 touch 处理里 preventDefault()。

演示二：识别滑动方向手势识别的通用套路

在方块上朝四个方向滑动手指，下方会显示方向与距离。核心只有三步：记起点 → 算差值 → 比较绝对值。

滑动识别器

阈值 30px
↕
按住后朝 上 / 下 / 左 / 右 滑
方向：— 横向位移：0 px 纵向位移：0 px
滑动方向判断JS
var lwj_startX = 0, lwj_startY = 0;

lwj_pad.addEventListener('touchstart', function (e) {
  var lwj_t = e.touches[0];        // 按下的第一根手指
  lwj_startX = lwj_t.clientX;
  lwj_startY = lwj_t.clientY;
}, { passive: true });

lwj_pad.addEventListener('touchend', function (e) {
  var lwj_t = e.changedTouches[0]; // 抬手时用它，touches 里已经没这根手指
  var lwj_dx = lwj_t.clientX - lwj_startX;  // 横向位移
  var lwj_dy = lwj_t.clientY - lwj_startY;  // 纵向位移
  var lwj_line = 30;               // 阈值：太小会误判成点击

  if (Math.abs(lwj_dx) < lwj_line && Math.abs(lwj_dy) < lwj_line) {
    console.log('这是一次点击，不算滑动');
    return;
  }

  // 谁大听谁的：横向大就是左右，纵向大就是上下
  if (Math.abs(lwj_dx) > Math.abs(lwj_dy)) {
    console.log(lwj_dx > 0 ? '向右滑' : '向左滑');
  } else {
    console.log(lwj_dy > 0 ? '向下滑' : '向上滑');
  }
});

🧠 为什么要阈值？手指按下去几乎不可能完全不动，几个像素的抖动会被误判成“滑动”。30px 是个经验值，卡片越大可以适当加大。

🚀 进阶思路：再加上“滑动速度”就能区分“慢慢拖”和“快速甩”——用 距离 ÷ 时间 计算，很多轮播库就是这样判断“轻扫翻页”的。

演示三：长按与双击时间维度的判断

长按：按下时启动定时器，600ms 内没抬手就算长按；抬手就取消。双击：记录上次点击时间，两次间隔小于 300ms 算双击。

长按 / 双击测试区

长按 600ms · 双击 300ms
长按我（0.6 秒） 或者快速点两下

结果：—

长按 + 双击JS
var lwj_timer = null;
var lwj_lastTap = 0;

el.addEventListener('touchstart', function () {
  lwj_timer = setTimeout(function () {
    console.log('长按触发');
  }, 600);
}, { passive: true });

el.addEventListener('touchend', function () {
  clearTimeout(lwj_timer);            // 抬手了，取消长按

  var lwj_now = Date.now();
  if (lwj_now - lwj_lastTap < 300) {
    console.log('双击');
    lwj_lastTap = 0;                  // 重置，避免三击被算成两次双击
  } else {
    lwj_lastTap = lwj_now;
  }
});

// 被电话、通知打断时也要清理定时器，否则状态会卡住
el.addEventListener('touchcancel', function () {
  clearTimeout(lwj_timer);
});

⚠️ 长按还会触发系统菜单（选中文字、图片另存）。记得加 user-select:none 和 -webkit-touch-callout:none（iOS）。

多指缩放与设备能力事件触摸之外的传感器

双指缩放的本质是“两指距离的变化”：算出当前两指间距，和上一帧比较，得到缩放比例。

双指缩放核心JS
// ① 算两根手指之间的直线距离（单位：像素）
function lwj_dist(t1, t2) {
  // Math.hypot(a, b) 就是勾股定理 √(a² + b²)，比手写 Math.sqrt 更直观
  return Math.hypot(t2.clientX - t1.clientX, t2.clientY - t1.clientY);
}

// ② 记住“上一帧”的两指距离，用来和当前帧做比较
var lwj_lastDist = 0;

el.addEventListener('touchmove', function (e) {
  if (e.touches.length < 2) return;  // 少于两根手指不处理（单指是拖动）

  // ③ 取当前两指，算出本帧距离
  var lwj_d = lwj_dist(e.touches[0], e.touches[1]);

  // ④ 第一帧没有“上一帧”，lwj_lastDist 还是 0，先跳过
  if (lwj_lastDist) {
    var lwj_scale = lwj_d / lwj_lastDist;  // >1 放大，<1 缩小
    console.log('本次缩放比例', lwj_scale.toFixed(2));
  }

  // ⑤ 把本帧距离存下来，下一帧就用它当“上一帧”
  lwj_lastDist = lwj_d;
}, { passive: false });  // 非被动模式，才能 preventDefault 阻止整页缩放

el.addEventListener('touchstart', function () {
  lwj_lastDist = 0;  // 新一轮手势开始，清空上一轮的距离
}, { passive: true });
代码里的关键点为什么这么写
Math.hypot(dx, dy)直接算两点直线距离，等价于 Math.sqrt(dx*dx + dy*dy)，少写乘法不易错
clientX / clientY两指必须用同一套坐标系（都用 client 或都用 page），混用算出的距离会错
scale > 1 表示放大两指间距变大 = 图片被“拉开”了，比例就是本帧相对上一帧的放大倍数
toFixed(2)日志里保留两位小数，避免一大串 0.999999 干扰观察
{ passive: false }告诉浏览器“我要阻止默认行为”，否则 preventDefault() 会失效并报警告
scale 是“每帧”的比例页面真正要用的“总倍数”要累乘：total = total * scale，并限制在 1～4 倍之间

还有三类在作业里很出彩的“设备事件”：

事件能做什么注意点
orientationchange / resize横竖屏切换时重排布局或重绘 canvasresize 会连续触发，记得防抖
deviceorientation陀螺仪：倾斜角度（α β γ），做“水平仪”“3D 视差”iOS 13+ 必须用户点击后调用 DeviceOrientationEvent.requestPermission()
devicemotion加速度：摇一摇、计步、晃动检测阈值判断 + 冷却时间，否则一次摇动触发十几次

⚠️ 传感器事件必须在真机上测，普通电脑浏览器收不到数据。写代码时一定要做“没有传感器”的降级分支，否则就是一片空白。

维度分值评分要点
事件理解25能说出四个触摸事件的触发时机、touches 三个列表的差别、为什么抬手用 changedTouches
